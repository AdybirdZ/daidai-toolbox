核查日期：2026-10-25；对应应用版本：1.0.6。

依据：[Open-Meteo 官方 Forecast API 文档 · Weather variable documentation](https://open-meteo.com/en/docs#weather_variable_documentation) 中的 **WMO Weather interpretation codes (WW)** 表格及其脚注。应用内“设置→天气→查看图例”底部链接到该位置。

## 代码范围与模型条件

本次官网表格列出的代码为：

`0, 1, 2, 3, 45, 48, 51, 53, 55, 56, 57, 61, 63, 65, 66, 67, 71, 73, 75, 77, 80, 81, 82, 85, 86, 95, 96, 97, 99`

这是 WMO 天气代码的一部分，不需要为未在接口文档中列出的每一个数字制作图标。图例覆盖本次文档列出的 29 个代码，额外保留“天气未知”的问号提示；“天气未知”没有独立 WMO 代码。

当前脚注原文：

> Codes 96 and 99 are only reported by models with an explicit hail forecast, such as DWD ICON or UKMO.

官方接着说明，其他模型从不稳定度参数推算雷暴，报告 95 和 97。因此本版本将 96、99 的条件表述为“模型提供明确冰雹预报”，没有沿用旧资料中“仅中欧地区”的说法。是否能返回这些代码取决于实际模型能力与覆盖范围，不能仅根据城市所属地区断定。

本次表格还列有 **97 · Heavy thunderstorm**，1.0.6 补上“强雷暴”名称和图标。既有代码的中文名称保持用户指定的对应表，包括 95“小或中雷雨”。图标由本应用绘制，官方接口只返回数值代码，不返回这些图标。

## “天气未知”的触发条件

当前天气、逐小时及逐日天气均使用相同的代码读取规则：

- 字段缺失、数组对应项缺失或值为 `null`。
- 值不能解释为有限、非负且在 Java 整数范围内的整数，例如文本 `bad`、小数 `3.5`、负数或溢出数值。小数不再截断成一个看似正常的天气代码。
- 返回一个有效整数，但没有包含在本版本支持的列表内，例如未来服务增加的新代码。

前两种情形使用内部占位值 `-1`；它不属于 WMO 代码，不在图例中显示成编号。第三种情形保留原始整数，但名称和图标统一使用“天气未知”与问号。正常返回本版支持的有效代码时不会出现该提示。网络失败仍按原逻辑显示失败信息或带时间标记的缓存，不会伪造实际天气。
